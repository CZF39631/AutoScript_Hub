# 1.3.0 旧客户端协议兼容验收

## 结论

安全源码快照服务与冻结 `1.2.4` Agent 的隔离 HTTP 验收通过：**27 项断言、40 次收到响应的真实 HTTP 请求，退出码 0**。另有一次指向本次占用但未监听 loopback 端口的真实连接失败，用于验证状态缓存补传。

这不是安装器验收、已安装客户端验收、生产环境验收或真实双设备验收；不能据此声称这些场景已验证。

## 覆盖范围

- 直接调用冻结 `authenticate`、`register_agent`、`send_heartbeat`、`_sync_script_authorizations`、`_sync_client_settings`，以合成 operator 用户验证真实登录、设备注册与授权。
- 冻结 `_poll_and_execute_locked` 实际查询 pending、claim、获取脚本元数据、下载 ZIP、执行冻结归档校验/安装，再读取合成有限进程的退出状态，分别上报 success/failed。
- 冻结 `_upload_log_delta` 的原始 `f.read()` 全量读取路径上传中文大日志；追加后 **1,680,013 UTF-8 字节**。验证服务确认偏移、从零重复上传、重复后重试、增量追加；最终服务日志逐字节相等，没有重复。
- 大日志最终 SHA-256：`15778bdba44d191914acc3c4664bd3ce13e8788b2d489293ee8690ff73aeb851`。
- 冻结 `_report_run_status` 在真实连接失败后写入待补传状态，恢复独占服务地址后 `_flush_pending_reports` 成功清空，再次调用无重复。
- 冻结本地执行/完成逻辑在离线状态下产生历史记录，恢复心跳后 `_sync_local_runs_locked` 真实走 execute → claim → log/chunk → status；第二次同步不新增执行，也不发送 POST/PATCH。
- 重放冻结 `frontend/src/pages/RunDetail.jsx` 的 `{run_id, title, description}` 工单载荷，成功创建；超长标题返回 422 且 `detail` 为字符串；未同意却要求附日志仍返回 422，不创建额外工单。
- 三字段旧工单返回 `diagnostic_state=not_collected`、`log_snapshot_available=false`，**不会自动采集诊断或附带执行日志**。冻结 UI 的“日志会自动附带”旧文案并不代表新服务行为；本次没有运行浏览器，也没有修改冻结 UI。

## 隔离与替代边界

- 新 OS 临时数据根；新服务子进程绑定 `127.0.0.1:0`，Windows 使用 `SO_EXCLUSIVEADDRUSE`，持有同一个监听 socket 交给 Uvicorn。
- 子进程环境按系统运行必需项白名单重建，随机合成凭据，关闭 external auth，不继承数据库、企业认证、代理或真实客户端配置；不运行部署脚本。
- 所有 requests 会话禁用环境代理/netrc，并在实际发送层限制 loopback；客户端只允许本次服务端口及短时占用的离线测试端口。保留实际 HTTP 请求构造逻辑，没有替换冻结 requests 调用。
- 旧客户端单独子进程优先导入 legacy 源码，独立 `ClientPaths`；不调用 `run_agent`/`initialize`，不启动本地客户端监听、GUI、更新器或已安装 Agent。
- 仅替代机器名/IP 探测、桌面通知、环境依赖准备及用户脚本子进程：有限假进程返回退出码 0/7，写入合成日志。没有运行真实用户脚本、安装 pip 依赖或验证私有 Python/安装包。
- 新服务使用正常 FastAPI 启动初始化/迁移及调度器；通过同一快照模型创建合成脚本、版本和授权用户，ZIP 下载仍走真实服务路由。
- 不操作生产服务或冻结 Tag；不清理其他进程。退出仅终止本次 Popen 服务，客户端子进程超时由 subprocess.run 回收；没有全局 kill。合成数据和日志刻意保留，不清理任何项目 `tmp/`。
- 本脚本不运行全量 pytest；父端随后在独立快照完成 **634 项全量回归通过**。本验收不代替真实双设备或旧安装包验收。普通旧控制请求仍受 1 MiB 请求上限约束，工单有新长度/同意限制；结果仅覆盖上述协议及输入范围，不承诺任意旧输入都被接受。
