开发分支：`feature/diagnostics-scheduling`。第二、三阶段的诊断和调度主链路已接通，以下为开发验证，不代表正式发布或生产验收。原布局预览分支未合入。

## 已实现

- 工单：管理员分项脱敏策略、降低保护风险确认、客户端白名单采集、逐项选择与服务器预览、明确同意后提交、固定快照、受控下载、1–365 天保留清理及过期墓碑。
- 应用日志：Agent/桌面端轮转日志；本地基础凭据保护不等于上传策略，也不是完整秘密识别。上传仍有权限、大小和同意边界。
- 服务端：设备独立凭据、固定版本双用户权限、设备本机接受/拒绝/撤销、任务与执行记录、CAS 领取/启动、取消和失联 unknown、终态幂等导入、旧 Run API 隔离及事务内操作审计。
- 调度：本机和远程手动/一次性/每日/每周，IANA 时区；只补最近一次、排队领取前重验过期、暂停/删除取消队列。unknown 保留槽，不根据失联推断已停止。
- 客户端：SQLite 意图与报告队列、离线调度、固定版本准备、准备与运行共用门禁/超时/取消、Windows Job 在用户代码之前绑定，Agent 退出清理后代；明确领取拒绝不会产生无效完成报告。
- 完成输出先按 UTF-8 限界再冻结重试，避免超长异常或结果阻止停止事实送达；截断日志丢弃首条残缺行。
- 页面：沿用原导航与主题，新增任务管理、本机授权确认、明确设备/版本的运行确认、运行状态和取消、S 前缀本机历史；800px 操作列固定可见。
- 迁移：0007 任务表使用冻结结构，0008 诊断快照；主应用及后台循环已接线，作业失败相互隔离。

- 隔离运行 `backend/tests client/tests shared/tests test`：**566 passed**，143.66 秒；包含发布契约、旧库收养和迁移，以及三个真实 Windows Job 合成进程测试。
