# 人员分组与脚本市场

人员分组用于控制用户能够接触哪些脚本，适合为不同部门、项目组或业务团队提供彼此独立的脚本市场。分组名称和说明完全由部署单位维护，系统不内置任何企业部门或私有角色。

## 权限原则

分组和角色相互独立：

- **角色**决定用户能执行什么操作。
- **分组**决定用户能访问哪些脚本。

| 能力 | 管理员 | 开发者 | 操作员 |
|---|---|---|---|
| 管理分组和用户归属 | 全部 | 不允许 | 不允许 |
| 查看脚本市场 | 全部脚本 | 所属分组 | 所属分组 |
| 上传脚本 | 可选择任意有效分组 | 只能选择自己的有效分组 | 不允许 |
| 管理脚本版本和状态 | 全部脚本 | 所属分组脚本 | 不允许 |
| 安装和执行 | 全部脚本 | 所属分组脚本 | 所属分组脚本 |

用户和脚本都可以同时属于多个分组。只要双方至少有一个有效分组相同，用户就能看到该脚本。脚本版本继承脚本本身的分组，不单独配置。

未分配分组的脚本只有管理员可见。管理员始终拥有全局访问能力，以便修复错误的权限配置。

## 升级兼容

数据库迁移会创建“默认分组”，并将升级前已有的用户和脚本加入该分组。因此升级完成后，原有用户看到的脚本市场不会突然变化。

管理员可以按以下顺序逐步拆分市场：

1. 在“用户管理 → 分组管理”中创建业务分组。
2. 编辑用户并选择所属分组。
3. 在脚本页调整脚本的可见分组。
4. 使用不同分组账号确认市场、详情、安装和执行权限。
5. 所有关联迁移完成后，再停用或删除不再使用的分组。

默认分组只影响以后创建且未显式指定分组的本地用户、首次登录的外部认证用户，以及旧版客户端未提交分组信息时管理员上传的脚本。

## 撤权行为

用户被移出分组或分组被停用后：

- 脚本会从市场和“我的脚本”中消失；
- 详情、版本、下载、预设、安装和在线执行均会拒绝访问；
- 原安装关系保留，以便重新授权后恢复，也允许用户主动卸载；
- 历史运行记录不会被删除；
- 客户端 Agent 在线同步后，会更新本地授权清单，失权脚本不再出现在离线列表，也不能通过本地 API 执行。

客户端升级后必须至少成功联网同步一次授权，才能使用原有缓存脚本离线执行。授权快照最长有效 7 天；服务器明确返回 `401/403` 时会立即清空快照，临时网络错误则允许在有效期内继续使用最近一次授权。

已经下载到电脑上的文件无法在设备完全离线时被服务器实时召回。分组撤权会在客户端下一次成功连接服务器并同步授权时生效；如果业务要求即时强制撤权，应同时采用设备管理、磁盘权限或禁用离线执行等措施。

## 外部认证

外部认证只验证身份，角色和分组继续由 AutoScript Hub 管理：

- 外部用户首次创建时加入当前默认分组；
- 后续登录不会覆盖管理员设置的角色或分组；
- 本功能不会读取、硬编码或自动创建外部系统中的部门。

这样可避免外部字段变化意外扩大脚本权限。若以后需要自动同步组织结构，应单独设计可配置映射和冲突处理策略。

## 管理注意事项

- 默认分组必须保持启用；如需更换，应先将另一个有效分组设为默认。
- 仍关联用户或脚本的分组不能删除，应先迁移关联。
- 停用分组会立即停止其授权，请先确认影响范围。
- 开发者不能把脚本分配到自己不属于的分组。
- 无权限资源统一表现为“资源不存在或无访问权限”，避免通过 ID 探测其他分组内容。
