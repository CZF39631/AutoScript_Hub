# 1.3.0-preview.1 补充验收

**后续客户端更新**：请使用 [独立体验版](1.3.0-preview.1-独立体验版验收.md)。下文的“客户端安装包无需更换”仅描述当时服务端兼容修复这一轮；旧客户端原型包现已归档，配套服务端兼容修正版仍可使用。

## 结果

- 在无私有配置的独立源码快照运行全量 Python 测试：**634 passed，19 个弃用告警，131.90 秒**。
- 直接加载冻结 1.2.4 原始 Agent 代码，验证 **27 项断言、40 次真实 HTTP 响应**；已核验导出代码与冻结 Git blob（仅在内存归一 CRLF）。
- 覆盖登录、注册、心跳、授权/设置同步、领取、真实 ZIP 下载、成功/失败上报、1,680,013 字节中文日志、重复/增量偏移、连接失败补传、旧离线导入第二次不重复、旧工单请求。
- 实际 WSS：拒绝未知 CA，信任测试 CA 后仍拒绝错误主机名，正确证书升级 101；后台收到 1012 后自动重连并再次 ready，停止后线程和 socket 回收。
- 实际 HTTP + WS 取消：取消变为 cancel_requested 并提示对账，设备槽仍保留；收到 stopped=true 的 cancelled 报告后才释放槽，再次提示对账。
- 测试 Compose 结构检查通过；本机没有 Docker CLI，没有构建/启动服务器镜像，也没有部署公司测试端。

## 本轮修复

1. 旧 Agent 一次发送全部未确认日志，新增 1 MiB 限额会令大日志永久重试。仅旧 log/chunk 恢复原载荷行为，并在读正文前验证身份、运行归属及受管记录限制；新的任务/诊断限额不变。
2. 旧 pending 查询显式排除受管执行和导入历史，防止异常历史状态阻塞旧客户端的 limit=1 轮询。
3. 工单校验错误返回安全字符串，避免旧界面直接渲染错误对象造成崩溃。长度与同意要求不放宽。
4. 新增独立测试 Compose 模板：独立服务名、项目名、命名卷、必填端口及独立密钥；默认仅 loopback、关闭外部认证，限定服务器容器资源。正式 Compose 未改动。

## 不应误解的边界

- 旧客户端使用原始协议代码，但用户脚本进程、依赖准备和桌面通知是合成替身；不是旧安装包或真实双设备业务验收。
- 旧三字段工单可以创建，但不会自动附带诊断，旧界面的自动附带文案仍不准确；普通控制请求保留体积上限，工单保留新长度限制。通过不代表任意旧输入都被接受。
- 测试端必须使用独立目录、端口/域名、数据库/卷和凭据；入口确认前不远程部署，不替换正式端、不读取生产数据。
- 未执行 Setup 覆盖安装、企业代理验收、远程部署、合并、推送或发布。
