# 1.3.0 调度接口契约（开发中）

本契约用于前后端和 Agent 并行实现。不是发布声明。所有 API 使用用户 Bearer JWT；设备专用 API 另须 `X-Device-Token`，秘密值由客户端生成并在 Windows DPAPI 中保存，服务端仅存哈希。

## 设备与授权

- `POST /api/task-devices/register`：`{device_uuid, device_secret, name, agent_version}`，返回 `{id, device_uuid, name, user_id, status}`。UUID 已存在时只允许同一用户凭原秘密重新注册，禁止重置他人凭据。
- `GET /api/task-devices`：管理员可查看全部，其余仅本人设备及自己拥有授权记录的设备。
- `POST /api/task-devices/{device_id}/grants`：请求 `{script_id, script_version}`，申请人由 JWT 决定，返回 `{id, device_id, requester_id, script_id, script_version, status}`，初始 pending。
- `GET /api/tasks/grants`：申请人的授权请求（管理员可查看全部）。
- `GET /api/task-devices/{device_id}/grants`：设备认证后查看该设备全部授权（含申请人显示名）。
- `POST /api/task-devices/{device_id}/grants/{grant_id}/decision`：设备认证，`{decision: accept|reject|revoke}`。只有持有本机凭据的 Agent 可确认；远程管理员身份不能替代设备同意。授权绑定用户、脚本和数值版本。
- `POST /api/task-devices/{device_id}/heartbeat`：设备认证，更新存活。

## 任务与执行记录

- `POST /api/tasks`：`{name, device_id, script_id, script_version, params, trigger, timeout_seconds, requires_desktop, requires_browser}`。超时 1–86400 秒，默认 600；两个条件默认 false。禁止调用者下发任意环境变量或解释器路径。须有效设备授权，且申请人与设备所属用户均拥有脚本访问权。版本从对应 ScriptVersion 配置验证，不使用 latest 配置。
- `GET /api/tasks`：本人创建的任务（管理员可查看全部）。响应条目包含上述字段及 `id, enabled, next_fire_at`。
- `POST /api/tasks/{id}/action`：`{action: run|pause|resume|delete, request_id?}`；手动运行须 UUID request_id，同一任务同一 request_id 只创建一次。
- `GET /api/tasks/executions`：本人任务执行（管理员可查看全部），返回含 `id, task_id, task_name, run_id, device_id, state, scheduled_for, error_msg` 的列表。
- `POST /api/tasks/executions/{id}/cancel`：本人或管理员；尚未领取直接 cancelled，否则 cancel_requested，不能谎称进程已停止。
- 任务执行关联现有 Run，但待执行状态用 `queued`，旧 `/api/runs?status=pending` 不能领取；旧 claim/status/log-chunk 路由拒绝接管受管任务。Run 所属人为任务创建人。

## 设备领取协议

以下路由均设备认证：

- `GET /api/task-devices/{device_id}/pending`：该设备未结束执行，含 queued、claimed、running、cancel_requested、unknown；有界列表。
- `POST /api/task-devices/{device_id}/executions/{id}/claim`：`{attempt_id: UUID}`。数据库事务同时占用设备执行槽并领取；同一 attempt 可幂等返回，别的 attempt 冲突。
- 领取返回：`{id, run_id, task_id, script_id, script_version, params, timeout_seconds, requires_desktop, requires_browser, state, attempt_id}`。
- `POST /api/task-devices/{device_id}/executions/{id}/start`：`{attempt_id}`。准备后再检查授权、取消和有效期，只从 claimed 转 running 时返回 `{can_start:true}`；重复请求返回 `{can_start:false}`，禁止丢失响应后盲目重新启动。
- `POST /api/task-devices/{device_id}/executions/{id}/report`：`{attempt_id, state: success|failed|cancelled|unknown, error_msg?, result_files?, log_tail?, stopped:true}`。确认进程已停止后才能释放槽；重复相同终态幂等，禁止晚到消息覆盖其他终态。日志最多 64 KiB，禁止客户端指定服务端文件路径。
- 领取或运行期间设备失联转 unknown，并暂停对应任务，不自动重分配或重启。设备恢复通过持久化账本核对后报告停止事实；unknown 不代表已确认脚本业务失败。

## 触发规则（共享模块 shared/scheduling.py）

`trigger`：`{kind: manual|once|daily|weekly, timezone: "Asia/Shanghai", start_at?: ISO带时区, time?: "HH:MM", weekdays?: [0..6], misfire: skip|run_once, grace_seconds: 300}`。

- once 必须 start_at；daily/weekly 必须 time；weekly 必须非空 weekdays（周一为 0）。
- 共享函数 `validate_trigger(dict)->dict`、`next_fire(trigger, after: aware datetime)-> aware datetime|None`（严格晚于 after）、`due_occurrence(trigger, scheduled_for, now)->bool`。
- manual 不自动触发；once 过期按错过策略记录 skipped。周期任务恢复时只考虑最近一次，不追赶整个积压。
- skip 只允许正常扫描误差 30 秒；run_once 允许 grace_seconds（1–86400）。时区显式记录，DST 不存在时刻跳过，重复时刻只触发一次。
- 发生项唯一键 `(task_id, revision, scheduled_for)`；手动发生项按 request_id 唯一。

## 本机 API（仅现有本地 Bearer + Origin 验证）

- GET `/local/schedules`，POST `/local/schedules`（同任务结构但无 device_id，固定缓存 script_version）。
- POST `/local/schedules/{id}/action`：`{action: pause|resume|delete|run, request_id?}`。
- GET `/local/schedule-events`：本机发生项列表（含跳过、未知、失败）。
- GET `/local/task-device`：设备公开身份和注册状态，不返回秘密。
- GET `/local/device-grants`：代理服务器设备授权列表。
- POST `/local/device-grants/{id}/decision`：代理同名设备决策；只能从本地用户操作触发。
- POST `/local/runs/{id}/cancel`：取消本机执行（含定时／远程执行）。

## 安全约束

本机、旧线上和新增远程执行共用执行门禁、参数校验、进程树生命周期和超时；准备阶段也占用槽。执行意图先落盘再启动，重启不自动重跑不确定任务。旧离线完成历史不可再通过 execute 接口生成 pending，应独立幂等导入完成记录。

设备授权意味着获授权者可提供脚本参数并以目标 Windows 用户权限运行固定版本；它不是任意脚本安全沙箱。脚本运行、路径访问及凭据使用须符合明确授权。
