# 多语言支持

## 当前范围

本轮在开发分支接入简体中文和 English，使用 `i18next` / `react-i18next`。这不是已发布安装包的功能声明，也不改变当前运行中的服务端或客户端。

- 登录页和主界面侧栏提供语言选择；切换无需刷新，不通过重新挂载页面清空表单。
- 导航、各管理页面的固定文案、通用参数控件、诊断控件和日志查看器框架使用词条。
- Ant Design 的内置文案与日期控件语言同步切换。
- 默认简体中文。偏好保存在当前页面来源的 `localStorage`，键为 `autoscript.ui.language`，与登录凭据分开；存储不可用时仍可切换当前页面，但无法保证下次启动记住选择。
- 偏好不跨设备同步；浏览器来源（协议、主机、端口）改变时，也不会自动继承。原生向导尚不负责保存此偏好。
- 所有翻译随前端打包，无需在线翻译服务，不会为翻译上传用户内容。

## 明确保留原文的内容

以下内容不是本轮翻译目标：

- 脚本名称、描述、脚本自带的参数标签和帮助文字；
- 用户输入、工单内容、原始执行日志、输出文件名和历史更新说明正文；
- Python 原生初始化向导、桌面通知、安装器自定义提示；
- 尚未建立稳定错误码的后端和本地 Agent 错误详情。

登录页对已知的旧版认证错误提供精确映射。其他未知错误保留安全原文，不把任意业务文本当翻译词条。下一阶段可增加“稳定错误码 + 参数 + 兼容 `detail`”，但不得破坏旧客户端协议。

## 不变的契约

语言仅影响显示：不修改 API 路径与字段、数据库状态值、审计动作值、脚本参数 key、脚本版本、权限或授权条件。

语言与时区独立。切换 English 不得修改任务的 `trigger.timezone`、执行时间或星期编号；现有服务端时间显示规则也不因语言改变。

## 代码组织

```text
frontend/src/i18n/
  index.js              独立 i18next 实例与切换入口
  useI18n.js            React 订阅接口
  preference.js         安全读取和保存语言偏好
  resources.js          汇总静态词条
  loginError.js         旧版登录错误兼容映射
  locales/
    shell.js            登录、导航、通用框架
    execution.js        调度和执行历史
    workspace.js        设置、脚本与诊断
    management.js       用户、工单及其余管理页面
```

词条采用稳定标识，中文和英文使用相同的 key；配置 `keySeparator: false`，点号是标识本身的一部分。

```jsx
import { useI18n } from '../i18n/useI18n'

function Example() {
  const { t } = useI18n()
  return <span>{t('shell.pendingSync', { count: 2 })}</span>
}
```

维护约定：

1. 新增固定界面文案时，同时增加中英文词条，不继续硬编码可见中文。
2. 使用完整句子与 `{{name}}` 插值，不拼接片段；计数使用 i18next 的复数能力。
3. 模块级状态映射保存词条 key，在渲染时翻译，不在模块首次加载时缓存翻译结果。
4. 不把语言用作页面 `key`，不在语言切换事件中创建、运行或停止业务任务。
5. React 渲染翻译结果，不通过 `innerHTML` 注入词条或插值。
6. 未找到英文时回退中文；测试应发现缺失词条，而不是依赖回退掩盖遗漏。

## 验证

在独立的前端源码快照中执行：

```bash
npm ci
npm test
npm run lint
npm run build
npm audit --omit=dev
```

词条测试检查中英文 key 对应、插值一致性、静态调用引用、偏好存储失败、复数和认证错误回退。浏览器验收应覆盖中英文切换、刷新持久化、切换时表单保留、原始脚本标签/日志保留、1440 和 800 像素布局，以及调度请求字段和时区不变。浏览器测试仅使用合成 API 与 Agent，不连接正式服务或已安装客户端。

原生向导、系统通知、安装器与可选脚本多语言元数据留待后续；不应将本轮描述为“整个产品及全部脚本已经双语”。
