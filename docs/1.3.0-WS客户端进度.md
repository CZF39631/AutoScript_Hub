# 1.3.0 WS 客户端进度

## 已完成

- 新增 `client/runtime/task_notifications.py`：独立守护线程维护可选 WS 通知；收到协议版本 1 的 `ready` / `sync_required` 仅设置主循环 Event，不调用 HTTP、不领取、不执行、不上报，也不更新在线时间。
- 连接 `/api/task-devices/{device_id}/events`，仅通过 `Authorization: Bearer ...` 与 `X-Device-Token` 握手头认证；禁止含用户信息、query、fragment 的服务端 URL；不使用秘密子协议。
- 显式 `suppress_origin=True`、`redirect_limit=0`，连接后另检查 handshake status 必须为 101（规避 websocket-client 不跟随重定向却标记 connected 的行为）；不跟随任何跨源或同源重定向。TLS 要求系统信任证书并校验 hostname。
- Socket 超时 5 秒；在读取 payload 前限制 frame 为 4096 字节，拒绝分片，未知/无效 JSON 忽略，支持 ping/pong。
- 重连采用带 jitter 的指数退避，最高 60 秒；稳定连接 30 秒后重置；404/405/426 能力缺失冷却 300 秒，不影响 HTTP 路径。
- 内部凭据快照在锁下替换；server/account/JWT/device id/device token 任一变化使旧代际失效并中断旧 socket；旧回调不能唤醒新代际。TaskDevice 提供仅内部使用的锁保护身份快照。
- 主循环使用可唤醒 Event wait，通知合并，消费发生在下一次 HTTP 工作之前；单次等待最短 0.5 秒限制通知风暴。仍保留空闲 5 秒 / 运行 1 秒轮询，不因 WS 在线暂停轮询。
- Agent 退出、GUI 排空请求、更新安装退出时中断 WS，join 最长 6 秒，退出代际不接受迟到消息。
- 业务 heartbeat 提前到旧补传之前；`agent_iteration` 返回实际 heartbeat 成功与否。TaskDevice heartbeat 先于 durable outbox flush；旧服务器仍能 flush legacy outbox。
- 旧 pending reports 和 pending logs 每轮各最多 1 条，失败/未完成轮转；单条日志最多读取上传 256 KiB，未完成保留补传，避免大日志一次读入内存。UTF-8 分块边界不破坏字符。
- 客户端依赖固定 `websocket-client==1.9.0`。
