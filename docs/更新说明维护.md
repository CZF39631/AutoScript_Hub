# 更新说明维护

客户端侧边栏的“更新说明”由 `frontend/src/data/releaseNotes.js` 提供，随客户端静态资源打包，因此在断网环境中也可查看。

## 发布前维护

1. 更新 `currentRelease.id`。每次更新必须使用新的、稳定且不含敏感信息的 ID。
2. 填写标题、摘要和分组后的更新条目。
3. 只有需要主动提醒所有客户端使用者的更新才设置 `important: true`。
4. 将上一版本移入 `releaseHistory`，历史版本默认折叠展示。
5. 执行前端测试、Lint 和生产构建。

Windows 构建脚本会把发布参数 `-Version` 注入前端。重要更新弹窗只在内置版本与本地 Agent 当前版本一致时出现，避免升级交接期间把新版本说明错误展示给旧 Agent。

## 提醒规则

- 普通更新不会自动弹窗。
- 重要更新仅在升级后首次运行并登录时弹出一次。
- 使用者关闭弹窗后，本版本不会再次提示。
- 使用者可勾选“以后默认隐藏重要更新弹窗”，也可在“更新说明”页面重新开启。
- 隐藏设置和已读状态仅保存在当前设备的浏览器本地存储中，不上传服务器。
