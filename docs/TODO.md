验收目标：出错能定位，敏感数据不无控制上传，执行风险可控。

#### 简单任务调度

依次实现本机定时执行、远程手动执行、远程定时执行，不引入工作流画布或复杂任务依赖。

- [ ] 本机支持一次性、每日、每周执行。
- [ ] 向明确授权的设备下发远程任务，支持设备拒绝及撤销授权。
- [ ] 支持集中配置定时任务，由目标设备领取执行。
- [ ] 固定脚本版本、参数与目标设备，升级执行版本需明确确认。
- [ ] 定义设备离线、休眠和错过执行时间时的处理策略。
- [ ] 防止重复领取、重复执行及不受控并发，支持超时和取消。
- [ ] 检测桌面会话、浏览器等执行条件是否可用。
- [ ] 记录下发与执行审计，提供失败通知。
- [ ] 补充授权、离线恢复、重复执行防护和取消等场景测试。

验收目标：单个脚本在指定时间、指定电脑可靠运行。

## 参考路线（不一定实施）

以下内容仅保留为调研方向，是否实施须根据真实需求、成本和安全评估另行确认，不作为阶段一至四的交付依赖。

### 第五阶段参考：AI 辅助

- 开发者侧：按平台契约生成脚本草稿、分析脱敏日志、解释代码、提出修复并展示差异。
- 员工侧：解释脚本用途及参数、辅助填写参数、解释失败原因并整理问题上报。
- 接入企业允许的模型服务，明确发送给模型的数据范围与脱敏规则。
- 不默认允许 AI 自动执行、发布脚本或读取任意本地文件。

### 第六阶段参考：隔离执行与规模化

- 评估低权限 Windows 执行模式。
- 评估 CubeSandbox 等服务器沙箱后端，保留需要本机桌面交互的 Windows Agent。
- 根据规模需求评估设备分组、批量下发、并发限制和结果汇总。
- 引入前验证隔离边界、Windows 脚本兼容性、部署成本及故障处理能力。
