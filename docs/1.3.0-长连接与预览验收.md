# 1.3.0 长连接与预览验收

## 设计

Agent 主动连接服务端 `/api/task-devices/{device_id}/events`，不需要公网 IP 或开放入站端口。HTTPS 地址对应 WSS；正式环境应使用可信证书和 WSS。

- WebSocket 只发送 `ready` / `sync_required` 通知，不传脚本参数，不直接启动脚本。
- Agent 收到通知后唤醒原 HTTP 对账循环，继续使用领取、唯一启动确认、停止报告和持久化重试。
- 首次连接及重连都对账；通知允许重复或丢失，数据库仍是状态依据。
- 保留原 HTTP 轮询作为兜底。连接失败不影响旧服务器的 legacy 执行入口，不把 WS 在线等同于业务心跳。
- 首版面向单服务端实例，按已提交数据的有界快照检测变化，因此事务回滚不会发送未提交任务。通知扫描和原定时派发是两件事：WS 不会消除调度器本身的扫描延迟。
- 不引入消息队列。后续多实例部署需要专门设计连接路由/跨实例通知，不能假定内存连接表跨进程共享。

## 认证与边界

握手用 `Authorization` 和 `X-Device-Token` 请求头，禁止把凭据放入 URL 或子协议。服务端复核 JWT、用户状态及设备凭据；客户端凭据变化时重建连接，不使用旧连接回调触发新会话。

本次不改变原 HTTP 注销语义，不新增用户会话撤销表或设备秘密轮换接口；不能宣称关闭连接就吊销了 JWT。用户禁用、JWT 到期与设备凭据失效应使连接关闭。

连接需要限额、心跳/超时、可中断退避、通知合并和退出清理。网络中断时远程取消无法立即送达，本机超时和进程树约束继续生效。对不确定业务结果仍不自动重跑。

## 反向代理

代理必须允许 WebSocket Upgrade，保留认证头，设置大于心跳间隔的读取超时。例如 Nginx 的对应路径需要：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 90s;
```

这是现有 `proxy_pass` 路径中的配置片段，不是可直接替换的完整站点配置。禁止缓存任务 API。代理不支持 Upgrade 时，客户端退回轮询；这不等于 WSS 已验收。

项目 Docker 入口和 Python 直接入口限制 WS 帧为 1024 字节、接收队列为 4；自定义 Uvicorn 启动命令也应带 `--ws-max-size 1024 --ws-max-queue 4`，不能只依赖应用收完帧后的检查。

## preview.1 交付约束

目标包名：`AutoScript-Hub-Setup-1.3.0-preview.1.exe`，渠道 `beta`，不创建正式 Tag 或远程 Release。

- 使用明确源码清单复制到 OS 临时目录构建，依赖安装在独立构建 venv；不扫描仓库根 `tmp/`、不复制私有配置。
- 安装包不能直接在维护电脑运行来做隔离验收：正式 AppId、用户数据和进程关闭逻辑可能影响现有客户端。
- 冻结准备验收采用临时安装布局、独立数据根和合成脚本；仅清理本次创建的进程。它不能替代覆盖安装、真实双设备和企业代理验收。
- 测试新功能需要配套 1.3.0 服务端。现有生产 1.2.4 不自动升级，也不会凭客户端安装包获得任务接口。应使用独立验证实例和独立数据卷。
- `packaging` 将 `preview.1` 解释为 `rc.1`：其顺序高于同版本 beta，低于正式 1.3.0；后续不能指望自动降级到同版本 beta。

实际构建、校验和测试结果在完成后另附记录，本文本身不是通过证明。
