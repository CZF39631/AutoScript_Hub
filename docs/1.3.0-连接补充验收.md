# 1.3.0-preview.1 连接补充验收

## 范围与隔离

本次仅新增 `backend/tests/test_task_notifications_tls.py` 和本文，不修改生产代码、现有测试或已暂存文件，不提交、不合并。

测试复制到维护端已有的无私有配置构建快照，在其独立虚拟环境中运行；运行前断言快照根目录不存在 `config.json`。没有在主工作树运行 pytest，没有读取主工作树私有配置、`.env` 或根目录 `tmp/`。

`DATA_DIR`、`DATABASE_URL`、`AUTOSCRIPT_CLIENT_DATA_DIR` 均指向新建的操作系统临时目录；设置 `EXTERNAL_AUTH_ENABLED=false`、`PYTHONUTF8=1`。服务仅绑定 `127.0.0.1` 的系统分配端口，凭据为测试合成值，不连接真实 Agent 或生产服务。证书和私钥仅写入 pytest 临时目录，不导入系统根证书。

## 本次实际结果

仅执行新增文件：

```text
python -m pytest -q backend/tests/test_task_notifications_tls.py
2 passed, 9 warnings in 1.83s
```

告警为 FastAPI、Starlette、anyio 和 websockets 的弃用提示；没有测试失败。本次未运行全套测试。

| 场景 | 实际验证 |
| --- | --- |
| 未知 CA | cryptography 临时生成 CA 与带 `127.0.0.1` IP SAN 的服务端证书，实际 Uvicorn WSS 握手抛出 `SSLCertVerificationError`，未进入 ASGI WebSocket 接受流程 |
| 显式信任 | 仅为测试 socket 设置 `ca_certs`；保持 `CERT_REQUIRED` 和主机名校验开启，实际握手返回 HTTP 101，并收到 `ready` |
| 后台自动重连 | 实际 `TaskNotifications` 后台线程连接受控 WSS ASGI 端点；首次 `ready` 后服务端关闭码为 1012；未再次 configure、未人工重启，自动建立第二次 HTTP 101 连接，后台再次消费 `ready` 并设置唤醒事件 |
| 清理与边界 | `stop()` 后后台线程结束、活动 socket 清空、创建的 socket 均已关闭；服务端线程有限等待后结束并关闭自有监听 socket；ASGI 记录的 HTTP 请求为空 |

重连测试保留生产重连退避逻辑，没有替换网络收发或缩短退避；仅通过派生类观察实际消息处理。启动、消息等待、连接和退出均有有限超时。受控端点仅发送通知，不调用任务领取、执行、提交等 HTTP API。

## 与既有证据的关系

父任务已报告既有 `test_task_notifications_transport.py` 通过真实 loopback Uvicorn/NotificationSocket 的 HTTP 101、数据库提交后指纹变化提示和设备 secret 变化关闭验证。本次没有重跑该文件；上述证据与本次 TLS、后台重连证据分开记录。

## 尚未覆盖

- 真实双设备 Agent、真实账号鉴权与设备调度的端到端验收。
- 正式安装包、真实企业证书链、反向代理、公网入口和生产网络环境。
- 主机名不匹配、证书过期、证书撤销及真实代理配置等 TLS 负向矩阵。
- 长期断线、系统休眠恢复、网络切换、退避上限及长时间稳定性。
- 真实 HTTP 领取/执行/提交、幂等恢复和通知与执行联动；本次刻意不发起执行动作。

结论：新增两项隔离 loopback 测试通过，不代表真实双设备或整体验收通过。
