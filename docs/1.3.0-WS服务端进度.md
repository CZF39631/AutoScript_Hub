# 1.3.0 WS 服务端进度

## 已实现

- 新增 `/api/task-devices/{device_id}/events`，主 app 仅注册 router，无全局扫描任务。
- 握手必须携带 Authorization Bearer JWT 和 X-Device-Token；拒绝任何 query string 及 Origin。
- 提取 `authenticate_access_token` 复用 HTTP 的 JWT/用户检查，复用 `task_service.device_auth`；每 1.5 秒用线程池内独立短 Session 重新认证并读取已提交快照，不传递 ORM。
- 快照：设备活动槽、活动执行 id/state/attempt_id/stopped（槽优先、非 queued 优先、limit 101）、授权 id/status（limit 200）。快照不触发 pending、授权写锁或状态转移。
- 首次发送 `{"type":"ready","protocol":1}` 后立即发送 `{"type":"sync_required","protocol":1}`；变化或距上次提示 30 秒再次发送 sync_required。消息不携带参数、Token 或任务内容。
- 全进程最多 128 连接、每设备 2；发送/关闭超时 3 秒，应用接收消息上限 1024 字节。独立收发任务，finally 注销并取消/回收任务；取消作用域屏蔽保证 ASGI 断开时清理。
- 固定 backend `websockets==15.0.1`。

## 验证

仅运行 `backend/tests/test_task_notifications.py`：**16 passed**，约 5 秒。DATA_DIR/DATABASE_URL 指向系统临时目录，PYTHONUTF8=1；未运行整套 DB 测试。测试独立 FastAPI + WS router，注入临时 session factory，并覆盖父 conftest 的自动 DB fixture（conftest 仍导入主 app，但不启动其生命周期）。

覆盖：双认证/缺失/非法/query/Origin/过期拒绝；ready 和首提示；提交后取消原地变化提示；未提交和回滚快照不变；连接后 JWT 到期、用户禁用/删除及设备 secret 改变关闭；设备/全局配额、超大消息、断开注销、周期核对、慢发送超时。首次测试暴露 ASGI 取消时注销泄漏，修复后全部通过。

## 边界与父端复核

- WS 是单实例 best-effort 提示，不替代 HTTP 轮询、授权检查或 CAS。截断窗口以外的变化可能直到强制定期核对才发现；客户端必须在 ready/sync_required 后核对 HTTP，并保留断连回退。
- 沿用 HTTP 当前语义：JWT 到期及当前用户/设备凭据实时校验；没有新增注销吊销表或 secret 轮换 API。
- 1024 字节是 ASGI 应用层检查，传输层仍受 Uvicorn/websockets 默认消息限制；慢连接测试验证发送超时原语，不代表真实网络压力测试。
- 不修改 tasks.py、task_service.py、client、根 tmp 或私有配置；未切分支、暂存、提交。main.py 和 requirements.txt 保留原有未提交内容，仅添加本任务行。
